# Deckie

A booth companion for DJs who play on gear that does not know their library. An iPad listens to the room,
names the playing track from the DJ's own crate, reads the pitch fader, shows what could come next and how to
bring it in, learns how the DJ mixes, and writes the set's tracklist. The music never leaves the DJ's devices.
An App Hold Media product. The working code name in folders, the Xcode target and the bundle id is still "deck".

Start with `BRIEF.md` (the hand-over from the Oct 2026 sprint that built the first version for one party), then
`docs/product/spec-condensed.md` (the two-page spec), `docs/product/00-decisions.md` (why) and
`docs/architecture/overview.md` (what the parts are). The evidence behind the spec is in `docs/research/`.

## Layout

```
deck-app/     the iPad app (SwiftUI, xcodegen; see deck-app/README.md)
mixer/        the analysis, scoring, planning and rendering lab in Python (see mixer/README.md)
pool/         the disc-curation pipeline and the phone page's data builder (see pool/README.md)
web-player/   the phone page Mike used to audition the discs
docs/         product spec and decisions, research reports, architecture, naming, sprint history, disc printouts
```

## Running the sprint pipeline from this folder

The audio is not in the repo. The scripts find it through one setting, which defaults to the original folder on
Christopher's Mac:

```
export DECKIE_MUSIC_ROOT="/path/to/the/music/folder"
```

`pool/newfiles/pool.json` carries paths relative to that folder; `mixer/candidates.json` and the feature files
carry absolute paths and are regenerated by `mixer/build_candidates.py`. Disc build outputs ("CDs v3", "CDs mix",
the phone page's hard-linked tracks) are written beside the audio, never into the repo.

The Python environment is `mixer/.venv` (Python 3.14; recipe in `mixer/README.md`). Run every script with the
venv's python and `-I`. `mixer/pairs.json` (61 MB) is not committed: `score.py` regenerates it from the committed
feature files in a few minutes.

The app: `cd deck-app && xcodegen generate`, then build with Xcode or `xcodebuild` (commands in its README). Its
bundled data comes from `deck-app/tools/prep_data.py`; the ShazamKit catalogue is built from the audio and is not
committed either.

## What is not here, on purpose

No audio, no catalogue of commercial recordings, no credentials. See `docs/product/00-decisions.md`, D3 and D10.
